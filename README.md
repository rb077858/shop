# Reembir — המדריך המלא להקמת החנות

החנות שלך רצה על Cloudflare, מקבלת תשלומים ב-PayPal ומעבירה את ההזמנות לאליאקספרס דרך **DSers** (חנות מסוג CSV).
כתובת החנות: **https://shop.reembir.com** (הדומיין הראשי reembir.com נשאר פנוי לכל שימוש אחר).
המדריך הזה מסביר את כל ההקמה דרך הדפדפן בלבד, בלי להתקין שום דבר ובלי שורת פקודה.

## 1. איך הכל עובד — התמונה הגדולה

```
 לקוח באתר shop.reembir.com
        │  בוחר מוצר, ממלא כתובת, משלם ב-PayPal / כרטיס אשראי
        ▼
 הכסף נכנס לחשבון ה-PayPal העסקי שלך  ──►  ההזמנה נשמרת במערכת  ──►  אתה מקבל התראה במייל
        │
        ▼
 בדף הניהול (shop.reembir.com/admin) ← לשונית DSers ← "הורדת קובץ הזמנות"
        │
        ▼
 מעלה את הקובץ ל-DSers  ──►  DSers מזמין מאליאקספרס עם כתובת הלקוח  ──►  אתה משלם לספק באליאקספרס
        │
        ▼
 הספק שולח ישירות ללקוח  ──►  מורידים מ-DSers את מספרי המעקב  ──►  מעלים אותם בדף הניהול
        │
        ▼
 הלקוח מקבל מייל עם מספר מעקב, ויכול לבדוק את הסטטוס באתר בדף "מעקב הזמנה"
```

**מה עולה כסף:**

| רכיב | מחיר |
|---|---|
| האתר, השרת ומסד הנתונים (Cloudflare) | חינם |
| DSers (תוכנית Basic) | חינם |
| מיילים ללקוחות (Resend) | חינם עד 3,000 מיילים בחודש |
| **עמלת PayPal** | בערך 3–4.5% מכל מכירה, ואי אפשר לוותר עליה |
| **המוצר באליאקספרס** | אתה משלם לספק על כל הזמנה, מהכסף שהלקוח שילם לך |

הרווח שלך = המחיר שהלקוח שילם, פחות עמלת PayPal, פחות מה ששילמת לספק.

## 4. שלב ב׳ — יצירת מסד הנתונים ב-Cloudflare

מסד הנתונים שומר את המוצרים ואת ההזמנות.

1. היכנס ל-<https://dash.cloudflare.com>.
2. בתפריט הצד: **Storage & Databases** ← **D1 SQL Database**.
   (אם אתה לא רואה את זה, חפש "D1" בתיבת החיפוש למעלה.)
3. לחץ **Create Database** (או **Create**).
4. בשם הכנס בדיוק: `reembir-shop`. באזור (Location) אפשר להשאיר את ברירת המחדל, או לבחור Eastern Europe (הכי קרוב לישראל).
5. לחץ **Create**.
6. בדף מסד הנתונים שנוצר, מצא את **Database ID**: מחרוזת ארוכה בנוסח `a1b2c3d4-1234-...`.
   **העתק אותה ושמור בצד.** תצטרך אותה בשלב הבא.

### יצירת הטבלאות

1. בדף מסד הנתונים לחץ על הלשונית **Console**.
2. בלשונית חדשה, פתח את הקובץ `schema.sql` מהריפו: <https://github.com/rb077858/shop/blob/main/schema.sql>
3. לחץ על כפתור ההעתקה (אייקון של שני ריבועים, **Copy raw file**) בפינה הימנית העליונה של הקובץ.
4. חזור ל-Console ב-Cloudflare, הדבק את כל הטקסט בתיבה ולחץ **Execute**.
5. אמורה להופיע הודעת הצלחה. בלשונית **Tables** אמורות להופיע 4 טבלאות: `products`, `orders`, `order_events`, `settings`.

> אם מופיעה שגיאה על כמה פקודות ביחד: הדבק ובצע כל פקודת `CREATE ...` בנפרד, מ-`CREATE` ועד הנקודה-פסיק `;` שלה.

## 5. שלב ג׳ — עדכון קובץ ההגדרות ב-GitHub

1. פתח את <https://github.com/rb077858/shop/blob/main/wrangler.toml>.
2. לחץ על אייקון העיפרון ✏️ (**Edit this file**) בפינה הימנית העליונה.
3. מצא את השורה:
   ```
   database_id = "REPLACE_WITH_YOUR_D1_DATABASE_ID"
   ```
   והחלף את `REPLACE_WITH_YOUR_D1_DATABASE_ID` ב-Database ID שהעתקת. המירכאות נשארות.
4. באותו קובץ אפשר לשנות גם את ההגדרות האלה:

| שורה | מה היא עושה | ערך מומלץ |
|---|---|---|
| `STORE_NAME` | שם החנות שמופיע באתר ובמיילים | `"Reembir"` |
| `STORE_CURRENCY` | מטבע התשלום | `"ILS"` (שקלים) |
| `SHIP_COUNTRIES` | מדינות שאליהן מותר להזמין | `"IL"` (רק ישראל) |
| `SHIPPING_FEE` | דמי משלוח. `0` = חינם | `"0"` (מומלץ לגלם את המשלוח במחיר) |
| `FREE_SHIPPING_OVER` | משלוח חינם מעל סכום (`0` = כבוי) | `"0"` |
| `CONTACT_EMAIL` | המייל שמוצג ללקוחות | `"support@reembir.com"` |
| `PAYPAL_ENV` | `"sandbox"` לבדיקות, `"live"` לתשלומים אמיתיים | בהתחלה `"sandbox"` |
| `USD_RATE`, `PRICE_MULTIPLIER` | רלוונטי רק לייבוא אוטומטי דרך ה-API של אליאקספרס (תוספת רשות) | אפשר להשאיר |

5. למטה לחץ **Commit changes...** ← שוב **Commit changes**.

## 6. שלב ד׳ — העלאת האתר ל-Cloudflare Pages

1. ב-Cloudflare: בתפריט הצד **Workers & Pages** ← **Create** (או **Create application**).
2. בחר בלשונית **Pages** ← **Connect to Git** (או **Import an existing Git repository**).
3. אם זו הפעם הראשונה, תתבקש לחבר את GitHub. אשר גישה לריפו `shop`.
4. בחר את הריפו `shop` ← **Begin setup**.
5. מלא:
   - **Project name:** `reembir-shop`
   - **Production branch:** `main`
   - **Framework preset:** `None`
   - **Build command:** השאר ריק
   - **Build output directory:** `public`
6. לחץ **Save and Deploy**. אחרי דקה-שתיים תקבל כתובת זמנית כמו `reembir-shop.pages.dev`.
7. פתח את הכתובת. אמור להופיע דף החנות עם הכיתוב "עדיין אין מוצרים בחנות". זה תקין.

> אם הבנייה נכשלה עם שגיאה על `database_id`: חזור לשלב ג׳ ובדוק שהדבקת את ה-ID הנכון, בלי רווחים.

## 7. שלב ה׳ — הגדרת סיסמאות ומפתחות

1. ב-Cloudflare: **Workers & Pages** ← `reembir-shop` ← **Settings** ← **Variables and Secrets**.
2. לכל שורה בטבלה: לחץ **Add** ← בחר סוג **Secret** ← הכנס שם (**בדיוק** כמו בטבלה, באותיות גדולות) וערך ← **Save**.

| שם | חובה? | מה לשים |
|---|---|---|
| `ADMIN_PASSWORD` | ✔ חובה | סיסמה לדף הניהול. לפחות 10 תווים, ארוכה ומסובכת (למשל 20 תווים אקראיים ממנהל סיסמאות) |
| `PAYPAL_CLIENT_ID` | ✔ חובה | משלב ז׳ |
| `PAYPAL_CLIENT_SECRET` | ✔ חובה | משלב ז׳ |
| `PAYPAL_WEBHOOK_ID` | מומלץ | משלב ז׳ |
| `RESEND_API_KEY` | מומלץ | משלב ח׳ |
| `EMAIL_FROM` | מומלץ | `Reembir <orders@reembir.com>` |
| `ADMIN_EMAIL` | מומלץ | המייל הפרטי שלך. לשם יגיעו התראות על הזמנות חדשות |

3. **חשוב:** סיסמאות ומפתחות נכנסים לתוקף רק אחרי העלאה מחדש.
   אחרי שהוספת את כולם: **Deployments** ← בשורה העליונה לחץ על `...` ← **Retry deployment**.

4. בדיקה: היכנס ל-`https://reembir-shop.pages.dev/admin/` והתחבר עם הסיסמה. בלשונית **הגדרות** יופיע סימן ✔ ליד כל מה שמוגדר.

## 8. שלב ו׳ — חיבור הכתובת shop.reembir.com

החנות תהיה בכתובת משנה (subdomain) של הדומיין שלך: `shop.reembir.com`. הדומיין הראשי `reembir.com` לא משתנה ולא מושפע. אם יש עליו אתר או מייל, הם ממשיכים לעבוד כרגיל.

1. **Workers & Pages** ← `reembir-shop` ← הלשונית **Custom domains** ← **Set up a custom domain**.
2. הכנס `shop.reembir.com` (בדיוק ככה, בלי `https://`) ← **Continue**.
3. Cloudflare יציג את רשומת ה-DNS שהוא עומד ליצור (סוג `CNAME`, שם `shop`, יעד `reembir-shop.pages.dev`). לחץ **Activate domain**.
4. הסטטוס יהיה בהתחלה **Verifying / Initializing**. תוך כמה דקות (לפעמים עד חצי שעה) הוא יהפוך ל-**Active**.
   גם תעודת האבטחה (HTTPS) מוגדרת אוטומטית.
5. פתח את <https://shop.reembir.com>. אמורה להופיע החנות.

> **שים לב:** אל תוסיף ידנית רשומת DNS בשם `shop` לפני השלב הזה. אם כבר קיימת כזו (למשל מניסיון קודם),
> מחק אותה קודם: הדומיין `reembir.com` ← **DNS** ← **Records** ← השורה `shop` ← **Edit** ← **Delete**. אחר כך חזור לסעיף 1.

> **ב-`wrangler.toml` כבר מוגדר** `SITE_URL = "https://shop.reembir.com"`. הכתובת הזו משמשת לקישורים במיילים ללקוחות. אם תחליף כתובת בעתיד, עדכן גם שם.

## 9. שלב ז׳ — PayPal

מתחילים ב**מצב בדיקה (Sandbox)**, עם כסף מדומה. עוברים לתשלומים אמיתיים רק אחרי שהכל עובד.

### 9.1 מפתחות בדיקה

1. היכנס ל-<https://developer.paypal.com> עם חשבון ה-PayPal העסקי.
2. למעלה בחר **Sandbox** (מתג Sandbox / Live).
3. **Apps & Credentials** ← **Create App**.
4. שם: `Reembir`, סוג: **Merchant** ← **Create App**.
5. העתק את **Client ID** ואת **Secret** (לחץ "Show" ליד Secret) לסודות `PAYPAL_CLIENT_ID` ו-`PAYPAL_CLIENT_SECRET` ב-Cloudflare (שלב ה׳).
6. ב-GitHub ודא שב-`wrangler.toml` כתוב `PAYPAL_ENV = "sandbox"`.
7. העלה מחדש (**Retry deployment**).

### 9.2 קנייה לדוגמה

1. ב-developer.paypal.com ← **Testing Tools** ← **Sandbox Accounts**. יש שם חשבון קונה מדומה (Personal). לחץ עליו כדי לראות את האימייל והסיסמה שלו.
2. הוסף מוצר לחנות (פרק 12), ובצע קנייה באתר עם חשבון הקונה המדומה.
3. אחרי התשלום אמור להופיע דף "תודה רבה! ההזמנה התקבלה", וההזמנה תופיע בדף הניהול בסטטוס "שולם".

### 9.3 מעבר לתשלומים אמיתיים

1. ב-developer.paypal.com העבר את המתג ל-**Live** ← **Create App** (שוב) ← העתק את ה-Client ID וה-Secret החדשים.
2. ב-Cloudflare החלף את `PAYPAL_CLIENT_ID` ו-`PAYPAL_CLIENT_SECRET` בערכים של Live (לחץ על הסוד ← **Edit**).
3. ב-GitHub שנה ב-`wrangler.toml` ל-`PAYPAL_ENV = "live"` ושמור (Commit).
4. בצע קנייה אמיתית קטנה בעצמך, ואז החזר את הכסף מדף ההזמנה בניהול (כפתור "החזר כספי").

### 9.4 Webhook (רשת ביטחון, מומלץ מאוד)

ה-Webhook מבטיח שהתשלום יירשם גם אם הלקוח סגר את הדפדפן בדיוק ברגע התשלום.

1. באפליקציה שיצרת (Live) גלול ל-**Webhooks** ← **Add Webhook**.
2. **Webhook URL:** `https://shop.reembir.com/api/paypal/webhook`
3. סמן את האירועים:
   - `Checkout order approved`
   - `Payment capture completed`
   - `Payment capture refunded`
   - `Payment capture reversed`
   - `Customer dispute created`
4. **Save**. העתק את **Webhook ID** שנוצר לסוד `PAYPAL_WEBHOOK_ID` ב-Cloudflare, והעלה מחדש.

> **כרטיס אשראי בלי חשבון PayPal:** כפתור "Debit or Credit Card" מופיע אוטומטית מתחת לכפתור PayPal ברוב המדינות.
> אם הוא לא מופיע, בדוק בחשבון PayPal העסקי ← **Account Settings** ← **Website payments** ש-**PayPal Account Optional** מופעל.

## 10. שלב ח׳ — מיילים ללקוחות

בלי השלב הזה החנות עובדת, אבל הלקוחות לא יקבלו אישור הזמנה ומספר מעקב במייל (הם עדיין יכולים לבדוק בדף "מעקב הזמנה" באתר).

### 10.1 Resend (שליחת מיילים, חינם)

1. הירשם ב-<https://resend.com>.
2. **Domains** ← **Add Domain** ← `reembir.com` ← **Add**.
3. Resend יציג 3–4 רשומות DNS. יש שני דרכים להוסיף אותן:
   - **קל:** אם מופיע כפתור **Sign in to Cloudflare** / **Auto configure**, לחץ עליו ואשר.
   - **ידני:** ב-Cloudflare ← בחר את הדומיין `reembir.com` ← **DNS** ← **Records** ← **Add record**, והעתק כל רשומה (Type, Name, Content) בדיוק כמו ב-Resend. ברשומות TXT/MX, ה-**Proxy status** צריך להיות אפור (DNS only).
4. חזור ל-Resend ולחץ **Verify**. לפעמים לוקח כמה דקות עד שהסטטוס הופך ל-Verified.
5. **API Keys** ← **Create API Key** ← שם `reembir` ← הרשאה **Sending access** ← **Add** ← העתק את המפתח (מתחיל ב-`re_`).
6. ב-Cloudflare הוסף את הסודות `RESEND_API_KEY`, `EMAIL_FROM` = `Reembir <orders@reembir.com>`, ו-`ADMIN_EMAIL` = המייל שלך. העלה מחדש.

### 10.2 קבלת מיילים מלקוחות (support@reembir.com)

1. ב-Cloudflare ← הדומיין `reembir.com` ← **Email** ← **Email Routing** ← **Get started / Enable**.
2. **Routing rules** ← **Create address**: בשם כתוב `support`, וביעד כתוב את כתובת ה-Gmail שלך.
3. Cloudflare ישלח מייל אימות ל-Gmail. אשר אותו.
4. מעכשיו כל מייל ל-support@reembir.com יגיע ל-Gmail שלך.

## 11. שלב ט׳ — DSers: חיבור החנות

### 11.1 הכנות ב-DSers (פעם אחת)

1. היכנס ל-<https://www.dsers.com> ובחר את חנות ה-CSV שיצרת.
2. **חיבור אליאקספרס:** אם עדיין לא חיברת, DSers יבקש לקשר חשבון AliExpress (Link to AliExpress). אשר עם החשבון שממנו תקנה.
3. **הגדרות מומלצות** (**Settings**):
   - **Order memo / Note to supplier:** הודעה לספק באנגלית, למשל:
     `Dropshipping order. Please do not include invoice, price or promotional material in the package.`
   - **Shipping / Default shipping method:** שיטת משלוח ברירת מחדל ל-Israel. מומלץ **AliExpress Standard Shipping** או **Cainiao Standard**, כי יש להן מספר מעקב.
   - **Phone number:** השאר את מספר הטלפון של הלקוח (חברות השילוח בישראל שולחות לו SMS).
4. באליאקספרס שמור אמצעי תשלום (כרטיס אשראי / PayPal), כדי שהתשלום לספקים יהיה מהיר.

### 11.2 טעינת תבניות DSers לדף הניהול (פעם אחת, מומלץ מאוד)

DSers מקבל קבצים במבנה מסוים. כדי שהקבצים שהחנות מייצאת יתאימו בדיוק, מעלים לדף הניהול את קבצי התבנית המקוריים של DSers:

1. ב-DSers, בחנות ה-CSV, היכנס ל-**CSV Upload** (לפעמים נמצא תחת **Orders** או בתפריט הצד).
2. הורד את שתי התבניות:
   - תבנית מוצרים: **import_products** (לפעמים כפתור "Download template" בחלק של Products)
   - תבנית הזמנות: **import_orders** (כפתור "Download template" בחלק של Orders)
3. בדף הניהול שלך: `shop.reembir.com/admin` ← לשונית **DSers** ← **שלב 0**:
   - ב"תבנית מוצרים" לחץ **Choose File** ובחר את `import_products`.
   - ב"תבנית הזמנות" לחץ **Choose File** ובחר את `import_orders`.
4. יופיע ✔ **נטענה** ליד כל תבנית, ומתחתיה רשימת העמודות. אם כתוב "עמודות שיישארו ריקות", אלה עמודות שהמערכת לא מכירה (למשל מספר הזמנה באליאקספרס או מספר מעקב). זה תקין, כי DSers ממלא אותן בעצמו.

> אם לא תטען תבניות, המערכת תשתמש בעמודות ברירת מחדל לפי התיעוד של DSers. זה אמור לעבוד, אבל התבנית המקורית בטוחה יותר.

## 12. הוספת מוצרים

כל מוצר צריך להיות בשני מקומות: **בחנות שלך** (כדי שלקוחות יקנו) וב-**DSers** (כדי ש-DSers ידע מאיזה ספק להזמין).

### 12.1 הוספת מוצר לחנות

1. מצא מוצר באליאקספרס והעתק את הקישור שלו, למשל `https://www.aliexpress.com/item/1005001234567890.html`.
   המספר הארוך (`1005001234567890`) הוא **מזהה המוצר**.
2. בדף הניהול ← **מוצרים** ← **+ מוצר חדש ידני**.
3. מלא:
   - **שם המוצר:** בעברית, קצר וברור (למשל "שעון חכם עמיד במים").
   - **מחיר מכירה:** בשקלים. כלל אצבע: לפחות פי 2–3 מהעלות באליאקספרס, כולל המשלוח.
   - **מחיר לפני הנחה:** רשות. מוצג כמחיר מחוק (למשל 199.90 מחוק ולידו 129.90).
   - **מזהה מוצר באליאקספרס:** המספר הארוך מהקישור.
   - **עלות בדולרים:** רשות, כדי לראות רווח משוער בכל הזמנה.
   - **תמונות:** בדף המוצר באליאקספרס לחץ קליק ימני על תמונה ← "העתק כתובת תמונה", והדבק. קישור אחד בכל שורה, והראשונה היא התמונה הראשית.
   - **תיאור:** טקסט בעברית. אפשר להשתמש בתגיות HTML פשוטות כמו `<p>` ו-`<b>`.
4. **אפשרויות (צבע/מידה):** אם יש למוצר כמה גרסאות, לחץ **+ הוסף אפשרות** לכל אחת. כתוב שם (למשל "שחור" או "שחור / L") ומחיר.
   סמן "אזל" כדי להסתיר אפשרות זמנית.
5. **שמירה**. המוצר מופיע מיד באתר.

### 12.2 העברת המוצרים ל-DSers

1. בדף הניהול ← **DSers** ← **שלב 1** ← **הורדת קובץ מוצרים**. יורד קובץ `dsers_products_<תאריך>.csv`.
   בקובץ יש שורה לכל אפשרות של כל מוצר, ולכל שורה **SKU קבוע** (למשל `uabma93q-112`). ככה DSers יודע בדיוק איזה צבע ומידה הלקוח הזמין.
2. ב-DSers ← **CSV Upload** ← בחלק של **Products** לחץ **Upload** (או "Import products") ובחר את הקובץ.
3. המוצרים יופיעו ב-DSers תחת **My Products**. (אם כבר העלית מוצרים בעבר, זה בסדר להעלות שוב את כל הקובץ.)

### 12.3 חיבור כל מוצר לספק באליאקספרס (Mapping)

זה השלב החשוב ביותר. בלעדיו DSers לא יודע ממי לקנות.

1. ב-DSers ← **My Products** ← מצא את המוצר ← לחץ **Mapping** (אייקון של שני חצים / "Map supplier").
2. בחר **Basic mapping** (ספק אחד לכל המוצר).
3. בתיבה **Supplier / Product link** הדבק את הקישור של המוצר באליאקספרס ולחץ **Import** / **Confirm**.
4. DSers יציג טבלה עם כל אפשרות מהחנות שלך (לפי ה-SKU), ולידה בחירה של האפשרות המקבילה אצל הספק (צבע, מידה).
   **בדוק כל שורה**: "שחור" אצלך חייב להיות מחובר ל-"Black" אצל הספק.
5. **Save**.
6. חזור על זה לכל מוצר חדש.

> **מתי חוזרים על שלבים 12.2 ו-12.3?** רק כשמוסיפים מוצר חדש או אפשרות חדשה. שינוי מחיר או שם בחנות לא דורש עדכון ב-DSers.

## 13. העבודה היומיומית עם הזמנות

### 13.1 הגיעה הזמנה

תקבל מייל "הזמנה חדשה" עם הפרטים. בדף הניהול ← **הזמנות** היא תופיע בסטטוס **"שולם — להזמין מהספק"** (צהוב).

**בדוק את הכתובת.** אם הלקוח כתב את הכתובת בעברית, בלשונית DSers יופיע ליד ההזמנה "כתובת בעברית" באדום. אליאקספרס לא תמיד מקבל כתובות בעברית, אז כדאי לתרגם:
1. לחץ על מספר ההזמנה ← **עריכת פרטי משלוח (באנגלית)**.
2. כתוב באנגלית את השם, הרחוב, העיר והמיקוד. אם חסר מיקוד, אפשר למצוא אותו באתר דואר ישראל.
3. **שמירת כתובת**.

### 13.2 שליחת ההזמנות ל-DSers (אפשר פעם ביום)

1. בדף הניהול ← **DSers** ← **שלב 2**. יופיעו כל ההזמנות ששולמו ועוד לא הוזמנו מהספק, כולן מסומנות.
2. לחץ **הורדת קובץ הזמנות**. יורד קובץ `dsers_orders_<תאריך>.csv`.
3. ב-DSers ← **CSV Upload** ← בחלק של **Orders** לחץ **Upload** (או "Import orders") ובחר את הקובץ.
4. ב-DSers ← **Open Orders** ← הלשונית **Awaiting order**. ההזמנות יופיעו שם.
   - בדוק שלכל מוצר מופיע ספק ושיטת משלוח. אם לא, המוצר לא עבר Mapping (סעיף 12.3).
   - אם DSers מסמן שגיאה בכתובת (בדרך כלל Province או City), לחץ על ההזמנה ← **Edit** / **Customer detail** ובחר את העיר והמחוז מהרשימה של DSers.
5. סמן את ההזמנות ← **Order selected products** / **Place orders to AliExpress**. DSers יוצר את ההזמנות באליאקספרס.
6. **תשלום לספק:** ב-DSers תופיע הזמנה בלשונית **Awaiting payment**. לחץ **Pay** (או היכנס לאליאקספרס ← **My Orders** ← **Awaiting payment** ← שלם על כולן ביחד).
7. חזור לדף הניהול ← **DSers** ← **שלב 2** ← **סמן את המסומנות כ"הוזמן מהספק"**. כך הן לא ייוצאו שוב בפעם הבאה.

### 13.3 מספרי מעקב (כל כמה ימים)

אחרי 2–5 ימים הספקים שולחים את החבילות, ו-DSers מקבל את מספרי המעקב.

1. ב-DSers ← **Open Orders** ← הלשונית **Awaiting fulfillment** / **Fulfilled**. סמן את ההזמנות ← **Export** (ייצוא ל-CSV או Excel).
   לפעמים יש גם קובץ עם "Successful orders" שכולל את מספר ההזמנה באליאקספרס ואת מספר המעקב.
2. בדף הניהול ← **DSers** ← **שלב 3** ← **Choose File** ← בחר את הקובץ שהורדת (CSV או Excel).
3. המערכת תזהה אוטומטית את העמודות: מספר ההזמנה שלנו (מתחיל ב-R), מספר ההזמנה באליאקספרס, מספר המעקב וחברת השילוח.
   אם זיהתה עמודה לא נכונה, בחר את הנכונה ברשימה הנפתחת, והטבלה תתעדכן.
4. בטבלה יופיע ליד כל הזמנה **יעודכן** (ירוק), **כבר מעודכן** או **לא נמצאה אצלנו**.
5. השאר מסומן "לשלוח ללקוחות מייל עם מספר המעקב" ← לחץ **עדכון X הזמנות**.
6. ההזמנות עוברות לסטטוס **נשלח**, והלקוחות מקבלים מייל עם קישור למעקב.

> **אפשר גם ידנית:** בדף ההזמנה בניהול, הדבק את מספר המעקב בתיבה "מספרי מעקב" ← **שמירה**. הלקוח יקבל מייל.

### 13.4 אחרי שהחבילה הגיעה

בדף ההזמנה ← **סטטוס** ← **נמסר** ← **שמירה**. זה לא חובה, אבל עוזר לך לעקוב.

### 13.5 לקוח מבקש החזר

1. בדף ההזמנה ← **החזר כספי**. השאר ריק להחזר מלא, או כתוב סכום להחזר חלקי.
2. לחץ **החזר כספי** ← אשר. הכסף חוזר ללקוח דרך PayPal מיד, וההזמנה עוברת לסטטוס "הוחזר".
3. אם ההזמנה עוד לא נשלחה מהספק, בטל אותה גם באליאקספרס (**My Orders** ← **Cancel order**) כדי לקבל את הכסף בחזרה.

### 13.6 סיכום הסטטוסים

| סטטוס | משמעות | מה עושים |
|---|---|---|
| ממתין לתשלום | הלקוח התחיל לשלם ולא סיים | כלום. לא מוצג ברשימה הרגילה |
| **שולם — להזמין מהספק** | הכסף אצלך | לייצא ל-DSers ולהזמין |
| הוזמן מהספק | הוזמן באליאקספרס | לחכות למספר מעקב |
| נשלח | יש מספר מעקב, הלקוח קיבל מייל | לחכות |
| נמסר | הגיע | סיום 🎉 |
| בוטל / הוחזר | בוטל או הוחזר כסף | — |

## 15. פתרון בעיות

**האתר מציג "התשלום עדיין לא הוגדר בחנות"**
חסר `PAYPAL_CLIENT_ID`, או שלא העלית מחדש אחרי שהוספת אותו (**Deployments** ← **Retry deployment**).

**כפתורי PayPal לא מופיעים / "לא ניתן לטעון את PayPal"**
בדוק ש-`PAYPAL_ENV` תואם למפתחות: מפתחות Sandbox עם `sandbox`, מפתחות Live עם `live`.

**לא מצליח להיכנס לניהול**
הסיסמה היא הערך של `ADMIN_PASSWORD` ב-Cloudflare. אם שכחת, שנה אותו (**Edit**) והעלה מחדש.

**DSers: "SKU not found" / "Product not found" כשמעלים הזמנות**
המוצר או האפשרות לא הועלו ל-DSers. חזור לסעיף 12.2, הורד שוב את קובץ המוצרים והעלה אותו.

**DSers: שגיאה ב-Province / City**
DSers דורש שהעיר והמחוז יתאימו לרשימה של אליאקספרס. ב-DSers לחץ על ההזמנה ← ערוך פרטי לקוח ← בחר מהרשימה.
אם העיר לא ברשימה, בחר `Other` וכתוב את שם העיר בשורת Address 2.

**DSers: אין ספק / "Not mapped"**
המוצר לא עבר Mapping. ראה סעיף 12.3.

**DSers: שגיאה בטלפון**
הטלפון מיוצא בפורמט `+972501234567`. אם DSers דורש פורמט אחר, תקן בעריכת פרטי הלקוח ב-DSers.

**הקובץ מ-DSers לא מזוהה בשלב 3**
בחר ידנית את העמודות ברשימות הנפתחות. הכרחי שתהיה עמודה עם מספר ההזמנה שלנו (מתחיל ב-R ואחריו 7 תווים).
אם מספר ההזמנה שלנו לא מופיע בקובץ, העתק את מספרי המעקב ידנית בדף כל הזמנה.

**הלקוחות לא מקבלים מיילים**
בדוק ב-Resend שהדומיין במצב **Verified**, ושהסודות `RESEND_API_KEY` ו-`EMAIL_FROM` מוגדרים. כתובת השולח חייבת להיות ב-@reembir.com.
ב-Resend ← **Emails** אפשר לראות כל מייל שנשלח או נכשל.

**לקוח אומר ששילם אבל ההזמנה לא מופיעה**
בדף הניהול ← **הזמנות** ← סנן **ממתין לתשלום**, ובדוק ב-PayPal ← **Activity** אם התשלום עבר. אם הגדרת Webhook (סעיף 9.4), זה כמעט לא קורה.

**מחלוקת (Dispute) ב-PayPal**
תקבל התראה. ענה בתוך PayPal ← **Resolution Center** וצרף את מספר המעקב. זו הסיבה לבחור תמיד שיטת משלוח עם מעקב.

## 16. תוספות רשות

### 16.1 התראות לטלגרם

1. בטלגרם פתח שיחה עם [@BotFather](https://t.me/BotFather) ← שלח `/newbot` ← בחר שם ← תקבל **token**.
2. שלח הודעה כלשהי לבוט החדש שלך.
3. בדפדפן פתח `https://api.telegram.org/bot<TOKEN>/getUpdates` (במקום `<TOKEN>` הדבק את ה-token), וחפש `"chat":{"id":` ואחריו מספר.
4. ב-Cloudflare הוסף סודות `TELEGRAM_BOT_TOKEN` (ה-token) ו-`TELEGRAM_CHAT_ID` (המספר). העלה מחדש.

### 16.2 חיבור ישיר ל-API של אליאקספרס (במקום DSers או בנוסף)

החנות יודעת לעבוד גם מול ה-API הרשמי של אליאקספרס. זה מאפשר ייבוא מוצר מקישור, כולל כל התמונות והאפשרויות, הזמנה בלחיצה אחת ומשיכת מעקב אוטומטית כל 6 שעות.
צריך להירשם כמפתח ב-<https://openservice.aliexpress.com>, ליצור אפליקציה מסוג Dropshipping ולחכות לאישור.
לאחר האישור: הוסף סודות `AE_APP_KEY` ו-`AE_APP_SECRET`, הגדר באפליקציה Callback URL `https://shop.reembir.com/api/ae/callback`,
והתחבר מדף הניהול ← **הגדרות** ← **חיבור חשבון אליאקספרס**.
למשיכת מעקב אוטומטית: ב-GitHub ← **Settings** ← **Secrets and variables** ← **Actions** הוסף `SITE_URL` (`https://shop.reembir.com`) ו-`ADMIN_PASSWORD`.

### 16.3 שכבת הגנה נוספת לדף הניהול

ב-Cloudflare ← **Zero Trust** ← **Access** ← **Applications** ← **Add an application** ← **Self-hosted**:
דומיין `shop.reembir.com`, נתיב `admin`, מדיניות **Allow** עם האימייל שלך. זה חינם עד 50 משתמשים.
